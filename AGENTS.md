# Smart DIY project operations

## Architecture
- User UI: `smart-diy-pc-assistant-web` (Vue 3); admin: `smart-diy-pc-assistant-admin` (Element Plus).
- Both frontends use same-origin `/api`, `/agent`, `/media`. All requests enter Java; Java forwards `/agent/**` to Python using HTTP/1.1 with immediate SSE flushes. Never point a frontend directly at the Python port.
- Java owns users, permissions, hardware, saved builds, community/news and uploads. Python owns Agent orchestration, crawling, history, RAG and tool events. Do not restore Java AI or the removed market module.
- Python authenticates each user/admin through Java `/api/auth/me`; do not trust frontend-supplied identity.
- History is a persistent sidebar with fold controls, default expanded. Global navigation defaults collapsed, its toggle sits in the main content title row, outside both sidebars. Keep desktop/mobile slider and route animations consistent. Respect reduced-motion preferences.

## Production server (verified 2026-10-21)
- SSH: `gouc@192.168.1.6`; never log in as root. Obtain credentials from the user/session, never write them in source/docs.
- Docker Compose project `smartdiy`, directory `/www/smartdiy-docker`, services `backend`, `agent`, `web`, `admin`; restart policy `unless-stopped`.
- Existing host MySQL `localhost:3306` / database `smart_diy_pc_assistant`, Redis `localhost:6379`, and Qiniu bucket/domain continue unchanged. Linux production uses host networking so these localhost services remain compatible. Java binds 127.0.0.1:8080; Python binds 127.0.0.1:8000. Only frontend ports 18088/18089 serve LAN HTTP.
- Existing config was copied to `/www/smartdiy-docker/secrets/application-server.yaml`, with obsolete `app.ai` removed. `secrets/backend.env` retains Qiniu/SMTP variables; `secrets/agent.env` holds model settings. Files must stay private (0600; directory 0700), never print them or `docker compose config` with resolved environment.
- Persistent data: `agent-data/` (SQLite knowledge, conversations, checkpoints/settings) and `uploads/`. Back up Agent SQLite with its backup API or with the Agent stopped; don't copy a live WAL database file alone.
- Host Cloudflare Tunnel config: `/etc/cloudflared/config.yml`; service `cloudflared`. Routes: `smartdiy.cctstudio.cn` -> localhost:18088; `admin-smartdiy.cctstudio.cn` -> localhost:18089; `api-smartdiy.cctstudio.cn` -> localhost:8080. Other hostnames are unrelated: preserve them.
- Canonical admin entry: `https://smartdiy.cctstudio.cn/admin/`; build admin with `VITE_PUBLIC_BASE=/admin/`. Vue Router uses `import.meta.env.BASE_URL`; Nginx strips `/admin/` when forwarding to the admin container. Test `/admin/assistant` and `/admin/knowledge` with direct refresh. The admin subdomain is an alias, not the main entry.
- User domain formerly pointed at Cloudflare Pages; its DNS now points at the existing tunnel. Do not redeploy the old uni-app Pages site.
- Legacy Jenkins job `smart-diy` still references the previous direct-deployment paths and has no configured triggers as of this verification. Do not run it for Docker releases; use `bash deployment/deploy.sh` until that job is explicitly migrated.
- Previous direct Java systemd unit `cct-smartdiy` is stopped/disabled to prevent port collision; old JAR/config remain in `/www/smartdiy`.
- Pre-migration backup: `/www/smartdiy-backups/20261021-130426` (MySQL dump, prior JAR/env/YAML, Tunnel config, DNS records). `last-backup` records the path. This folder is private.
- Imported 78 legacy conversations and 250 messages into Agent SQLite using `scripts/import_legacy.py`; original MySQL tables remain intact. Import is idempotent and must run with Agent stopped. Never replace production data with local QA fixtures.

## Build, release and verify
1. Backend: `cd smart-diy-pc-assistant-backend && bash mvnw clean test package`. User frontend: `npm ci && npm run build`; admin: `npm ci && VITE_PUBLIC_BASE=/admin/ npm run build`. Agent: `.venv/bin/python -m pytest -q`.
2. Run `bash deployment/package-release.sh /absolute/staging-directory`; upload that staging directory into the production directory (do not use `rsync --delete` against secrets/data).
3. Use `deployment/compose.production.yaml`, not the development compose with a fresh MySQL. On server: `docker compose build` then `docker compose up -d --wait`. If the standard registry is unavailable, use a reachable trusted mirror explicitly; never change global Docker configuration or restart Docker (other workloads share it). `PIP_INDEX_URL` can select an accessible package index during Agent build.
4. Verify all four container health checks; `/api/health`, `/agent/health` via frontend origin; authenticated settings GET/PUT, upload+retrieval, actual streamed run and tool history. Check desktop/mobile visual layout and animations, then the public domains through Tunnel. Builds alone are not acceptance.
5. Never ship `application-local.yaml` inside a JAR/image. Maven resource exclusions and staging validation enforce this. Never commit secrets, test tokens, runtime databases or `.codex_tmp`.
6. Rollback: stop application Compose services, restore previous Tunnel/DNS configuration from the private backup if necessary, then remove `/etc/systemd/system/cct-smartdiy.service.d/docker-migration.conf`, run `systemctl daemon-reload` and `systemctl enable --now cct-smartdiy` only for an explicitly chosen legacy rollback. Preserve new Agent data. Restore MySQL only when a real schema/data rollback is necessary and after reviewing new writes; never blindly overwrite the live database.

## RAG/admin
- `/assistant`: endpoint/key/model, optional embedding model, time/step/tool/token limits, extra prompt, RAG chunk length/overlap/top-K/cosine threshold. Changes persist in Agent SQLite. Blank API key retains the current key.
- `/knowledge`: text/PDF/Markdown/TXT/URL imports, search preview, per-document reindex/delete. Reindex after changing chunk settings or embedding model. Without embeddings, retrieval uses keyword matching; do not claim vector search is enabled.
- `/runs`: execution status and events. JD search panel returns observed page prices and unknown availability; do not infer stock. Risk-control responses are reported, never bypassed.

## Chat UI and legacy compatibility (2026-10-21)

## IPv6 direct entrance and repeatable deployment
- Direct domain is exactly `https://v6-smartdiy.cctstudio.cn`, DNS-only AAAA (no A). Main Tunnel domain remains `https://smartdiy.cctstudio.cn`. Both reverse proxy the same web container at 18088 and share the same Java/Python/data/admin deployment. Never create a second copy of application data or a separate frontend build for IPv6.
- Host Nginx config `/www/server/panel/vhost/nginx/smartdiy-ipv6.conf` is rendered from `deployment/nginx-ipv6.conf.template`. The `[::]:443` default server rejects unknown/missing SNI before presenting a certificate; the named server also rejects mismatched HTTP Host. Do not add wildcard/default certificates to that listener. Other existing host workloads and Tunnel routes must be preserved.
- Server files `ipv6-hostname` and `ipv6-https-port` under the deployment root describe the entrance. `ipv6-address` records the initial observed address only; DDNS may change it. Resolve current AAAA when checking the endpoint.
- Existing `ddns-go` service updates the AAAA via its Cloudflare provider and `enp4s0`; private config `/root/.ddns_go_config.yaml`. Preserve all unrelated records/provider credentials. DNS configuration backup is `backups/ddns-before-smartdiy-ipv6.yaml`.
- Public Let's Encrypt ECDSA certificate uses acme.sh DNS validation. Installed cert/key: `/www/smartdiy-docker/certs/v6-smartdiy.cctstudio.cn/{fullchain.pem,key.pem}`; renewal state `/root/.acme.sh/v6-smartdiy.cctstudio.cn_ecc`. Existing acme.sh renewal reloads host Nginx after successful installation. Never commit keys or Cloudflare credentials.
- Normal release: run `bash deployment/deploy.sh` from the checkout (optional `SSH_IDENTITY_FILE=/path/to/key`). It connects as gouc, requests sudo password once without saving it, tests/builds Java and Python and both Vue apps, packages and uploads one release, backs up SQLite online and prior images/configs, then recreates the four application containers. No database/object-storage reset occurs.
- The script verifies container health, user/admin pages, Java/Agent health, identical user/admin release manifests through localhost, Tunnel and IPv6, browser CORS preflights, and rejected unknown/no-SNI/incorrect-Host traffic. It only prints SUCCESS after all checks pass. Failed application releases restore prior images/configs/build context; persistent data is preserved. Review logs/backups before any data rollback.
- First-time DNS/certificate/DDNS provisioning is separate from routine release. Subsequent releases reuse those settings. `deployed-commit` and `last-release-backup` under the server deployment root identify the current revision and recovery location.

## Product cards and streaming acceptance (2026-10-21)
- The welcome AI emblem stays still through counter-rotation; its three colored dots orbit around it while also floating up and down with staggered phases on desktop and mobile. Disable all motion for reduced motion.
- Requirement chips are independent single-choice buttons with a black selected state and no checkmark; never apply the navigation slider directive to them. Keep the numeric budget range control separate.
- ProductParts renders the same image/title/model/specification/price/JD-link structure for Agent drafts, saved-build previews/details and shared snapshots. Drafts normalize partSelections into the view; do not lose quote metadata when saving or editing. Preserve unknown prices and missing images explicitly rather than inventing replacements. Mixed GPU variant listings and MATX-only cases must not be treated as exact GPU/ATX-case matches; leave old captured snapshots intact.
- Build detail has a fixed header/footer, a body scrollbar at the right edge, rounded compatibility details and bounded desktop height; mobile remains full screen. The ordinary page scrollbar belongs to the viewport, not a centered max-width content box.
- Live model text is visible in the main reply area as it arrives. Keep public plans/work summaries in expandable details; never expose private chain-of-thought. Keep complete per-turn text across token flushes. The current microbatch threshold is 24 characters or 80 ms, with SSE polling every 250 ms and heartbeat frames every 5 seconds. Do not buffer/gzip the SSE route. Provider first-token latency still exists; show actual waiting/elapsed state instead of fabricated reasoning.
- A real local Kimi run through Java produced 105 text_delta frames from 20.68 s to 35.81 s and completed at 39.08 s. A streaming regression test verifies partial output while the run is still active and complete, untruncated final text. This is one measurement, not a response-time guarantee.
- Conversation rows expose latest run status and show a spinner for queued/running tasks; the list refreshes while the chat page is visible. Stop must be an outlined icon-and-text button. Keep menu triggers inset from the row edge and separate list content from its scroll track.
- Every completed AI reply has copy, regenerate and share actions. Regeneration creates a branch up to the selected answer's preceding request, preserving the original and later messages. Sharing can stop at a selected reply; it never publishes later messages. Historical drafts remain attached to their corresponding replies and are included read-only in explicitly shared snapshots.
- When a configuration card exists, answer prose explains choices/tradeoffs rather than repeating product tables and URL lists. The legacy display adapter hides only explicitly titled duplicate sections and preserves stored Markdown and general-purpose tables.

- Deployment incident: a disabled `cct-smartdiy` systemd unit was still retrying with Restart=always and claimed 8080 during container recreation. Disable alone does not stop an active/retrying unit. The release preflight installs `/etc/systemd/system/cct-smartdiy.service.d/docker-migration.conf` with `ConditionPathExists=!/www/smartdiy-docker/compose.yaml`, then explicitly stops/disables this exact legacy unit and checks that any 8080 listener belongs to the existing backend container before building/replacing application images. It must not kill an unrelated listener. After fixing the collision, wait for the backend health check to recover before starting the dependent Agent.

## Long tasks, retry durability and observed prices (2026-10-21)
- Legacy short persisted timeouts upgrade on Agent startup: model timeout 1800 s, run timeout 3600 s; administrator values above the minimum are preserved. Admin bounds are model 1800–7200 s and run 1800–14400 s. Java/Nginx allow 15000 s; SSE heartbeats stay enabled. Do not remove step/tool limits.
- Transient connection, rate-limit, provider-server errors and timeouts retry at most three times, after 5/15/30 s, from the same checkpoint. Authentication, invalid model/settings and exhausted steps require correction rather than an endless retry. Keep the user-selected free model.
- Run snapshots include an event cursor read together with current state. Retry publishes a new queued event; the UI resumes after its snapshot cursor, never replaying an earlier terminal state as the current state. Browser transport loss reconnects from a fresh snapshot.
- Stream microbatches persist partial text and events together. Final model output also persists an idempotent assistant message immediately, before subsequent checkpoint/title work. Interrupted fragments remain available as public saved content when a new model turn starts; preserve prior work summaries across retries. Never manufacture a final answer from summaries or reveal hidden reasoning.
- SKU errors return exact queried candidates for that hardware ID; blank SKU only selects automatically when exactly one verified candidate exists. Expensive GPU/RAM/SSD quotes are not mismatches merely because they exceed historical prices; use observed quotes and captured timestamps, adjusting parts to budget rather than inventing lower prices.
- Prefer explicit public final/after-coupon/subsidy prices, preserving conditions and page-price provenance. JD `lowestPrice=1` is a flag, not one yuan; masked digits and coupon amounts are not usable prices. Public detail pages can require login before showing final price: retain and label the observed page quote in that case. Never bypass risk control or infer a hidden settlement amount. Saved build snapshots retain price type/label/conditions without rewriting older snapshots.

- Production recovery also encountered provider HTTP 502 “Model resources are currently busy”, wrapped by LangChain as `OpenAIAPIError`. Classify provider errors with `isinstance` against SDK base exceptions (including LangChain subclasses), never exact class-name strings. The same bounded retry applies to wrapped 429/502/connection errors; this is not a model-ID mismatch.


## Conversation completion and interaction refinement (2026-10-21)
- Full build requests cannot complete with prose alone. Runtime checks that the current run has a validated draft containing CPU, motherboard, memory, storage, PSU, case and cooler, plus a GPU when explicitly required. At most two internal completion reminders are allowed inside the overall deadline; missing tradeoff decisions become `needs_input`, not false success. Consultation-only replies remain ordinary answers. Do not invent hardware, prices or compatibility to satisfy this gate.
- `ask_user` supports bounded structured options. Waiting questions/options survive refresh; choices resume the same checkpoint. A synthetic finalization question without a graph interrupt resumes with the user's message rather than an invalid resume command. Explicit numeric budget changes come from actual user answers; generic performance preferences do not authorize increasing the budget.
- Completed historical full-build runs without a complete card expose a derived continuation flag, without rewriting original messages/status. An explicit choice creates a new owned run via `completion_of`, preserving the original requirements/budget as execution context while storing only the actual user choice in chat. Internal completion instructions are system messages in the checkpoint, never fabricated customer messages.
- Assistant prose uses “在京东获取/查询”, never “爬取/抓取”. Chinese quoted bold text with spaces inside `**` renders as strong emphasis, while code and other Markdown remain intact and sanitized.
- Desktop feedback and feedback history open in a bounded rounded dialog without leaving the current route; submission controls stay in its fixed footer. Mobile keeps dedicated feedback pages. Ordinary page tabs are horizontally centered; requirement choices stay independent buttons.
- Welcome dots rotate while each dot's counter-rotated coordinate frame floats vertically on the screen by the same ±7 px, with staggered phases. The central AI disc stays static; reduced motion disables all animation. User bubbles have equal 20 px corners and a right offset, assistant replies sit further left.
- Clicking the brand Logo always starts an empty conversation and never cancels an active run. From another page, the chat navigation link returns to an owned queued/running conversation, preferring the last viewed active chat, otherwise the newest active chat. It fetches current history instead of trusting a stale local status. A newer navigation action must win over an older pending history request.
